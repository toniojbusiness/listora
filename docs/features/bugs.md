# Bug bash

The bugs found by driving the whole app as a reseller would, on the iPhone 17 and iPhone SE
simulators against the local stack with every fake (`npm run dev:api`, `dev:worker`, the fake
AI, fake eBay, fake Depop, and the fake marketplace sites), plus API probes for edge cases. Each
row says how to see it, what fixed it, and where its regression test is. Open items at the end
are follow-ups, not fixed here.

Edge cases probed through the API that held: a stale `expectedVersion` is `409 version_conflict`,
a replayed `Idempotency-Key` returns the first response, a reused key with another body is `409
idempotency_key_reused`, concurrent requests with one key get one item and `409
idempotency_key_in_progress`, titles over 200 characters are `422`, emoji titles round-trip, and
listing prices of $0 or less are refused.

## Open (follow-ups)

- The batch rapid review (`BatchReviewView`) lists a missing clothing size under "Check these" but
  still approves without it, to keep one tap per item; such an item gets its size on the item
  screen before it can be listed.
- Today has no card for a failed listing change ("Publish failed"); it shows only on the item
  screen.
- When Today's reload fails or hangs, it keeps the last cards (by design) with no sign that they
  may be out of date; a canceled sale's "Ship" card stays until the next successful load.
- An assisted Mercari, Poshmark, or Depop task copies the title, description, and price, but not
  the brand, size, condition, or category the marketplace's form also asks for.
- After a canceled sale, the sale's delist section still says "Delisted everywhere" after the
  seller relisted.
- "Check these (N)" counts the rows in the section, so it does not drop as the seller fixes them,
  while Next (N) does.
- Development only: the fake marketplace sites' pages have no viewport, so they render tiny in
  the app's sign-in sheet; `npm run dev:fake-ebay` sends its consent back to port 3000 unless
  `EBAY_FAKE_CALLBACK_URL` is set; the worker's eBay notification check fails when it starts
  before the API.
- The simulator runtime used here draws emoji as boxes everywhere (Safari too), so emoji in titles
  could not be checked visually; the API stores and returns them correctly.
